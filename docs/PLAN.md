# TrollKnight 프로젝트 계획

작성일: 2026-10-14 · 상태: MVP 1~4단계 구현 완료, 5단계 이후 예정

## 1. 목적

온라인에서 소모적인 논쟁을 유발하는 이용자에게 AI가 대신 응답하여, 실제 이용자가 직접 대응하며 쓰는 시간과 감정적 부담을 줄인다.

- 토론 승리나 설득이 목표가 아니다.
- 성공 기준은 "AI와 오래 대화했다"가 아니라 **실제 이용자의 대응 부담이 줄었는가**이다.
- 어그로성 행동이 다른 이용자에게 줄어들었는지는 별도로 검증한다. 이는 코드로 자동 측정되지 않는다.

## 2. 원본 저장소 분석 결과 (LukasBialozor/MultiAgentDebate)

확인 방법: `git clone --depth 1` 후 소스 열람. **원본 앱은 실행하지 않았고 원본 테스트도 돌리지 않았다.**

| 항목 | 확인 내용 |
|---|---|
| 스택 | Python, FastAPI, AsyncOpenAI, WebSocket, ChromaDB, sentence-transformers, 바닐라 JS |
| 규모 | 약 7,600줄 (백엔드 2,700 / 프론트 2,150 / 테스트 1,400) |
| 라이선스 | MIT. 고지문 유지 시 수정, 재배포 가능 |
| LLM 연결 | OpenAI 호환 `base_url` 교체 방식. DeepSeek 기본, Ollama / LM Studio / vLLM 가능 (코드상 확인, 실행 미검증) |
| 대화 구조 | 닫힌 루프 `for round: for agent:`. 종료 조건은 라운드 수(최대 6) 하나 |
| 없는 것 | 시간 / 비용 한도, 중단 명령, 반복 감지, 안전 정책, 대화별 성과 지표, 외부 입력 기반 응답 |

### 재사용 판정

| 구분 | 대상 |
|---|---|
| 그대로 재사용 | OpenAI 호환 클라이언트 (`deepseek_client.py`), 아카이브 경로 검증 (`archive.py`) |
| 수정 후 재사용 | 토큰 사용량 기록, 설정 저장소, 페르소나 저장소 구조, CORS / Origin 검사 패턴 |
| 새로 구현 | 대화 엔진, 한도 정책, 반복 감지, 안전 정책, 승인 흐름, 지표 |
| 제외 | RAG(ChromaDB), 프론트엔드, 28개 실존 인물 페르소나 |
| 미확인 | 원본 앱 기동 여부, 원본 테스트 통과 여부, 로컬 모델의 `stream_options.include_usage` 지원 |

### 저장소 전략

**독립 저장소.** 원본의 핵심 루프, UI, RAG를 대부분 쓰지 않으므로 포크의 이점(업스트림 병합)이 없다. 필요한 파일만 MIT 고지(`THIRD_PARTY_NOTICES.md`)와 함께 가져온다. 재사용 비율은 약 20~25%.

## 3. 현재 구조

```
src/trollknight/
  llm/      base.py(LLMClient 프로토콜, FakeLLM) · openai_compat.py(원본 이식)
  convo/    engine.py(상태, 한도, 지표) · repetition.py(반복 감지)
  persona/  models.py(말투 설정, TOML) · policy.py(안전 규칙과 출력 검사, 분리)
  review/   session.py(승인 흐름, JSONL 로그)
  cli.py    시뮬레이션 CLI
personas/   deadpan.toml
tests/      23개
```

설계 원칙: 페르소나(말투)와 안전 정책을 분리하고, 대화 엔진은 `LLMClient` 프로토콜에만 의존하므로 모델 교체 시 엔진이 바뀌지 않는다.

## 5. 핵심 동작 규칙 (구현됨)

- `draft_reply`는 초안만 만들고 전송하지 않는다. 모든 초안은 사람의 결정(승인 / 수정 / 폐기 / 중단)을 거친다.
- 안전 검사에 걸린 초안은 그대로 승인할 수 없다. 수정해야 하며 수정문도 다시 검사한다.
- 폐기한 초안은 이후 모델 맥락에서 제거된다. 수정한 초안은 실제 보낸 문장으로 대체된다.
- 한도에 도달하면 이후 생성을 하지 않는다. 사용자는 언제든 중단할 수 있다.
- 결정과 이벤트는 JSONL로 기록한다.

## 6. 남은 작업 상세

### 5단계: 지표와 리포트
- 이용자 추가 대응 횟수와 대응 시간은 사람이 입력한다 (세션 종료 시 입력, 또는 별도 기록 명령).
- 세션별 리포트: 총 시간, 응답 수, 평균 생성 시간, 반복 비율, 차단 건수, 토큰, 추정 비용.
- 세션 간 비교(도입 전후)는 수동 입력값을 기준으로 한다.
- "어그로가 줄었는가"는 자동 판정하지 않고 사람이 기록하는 항목으로 둔다.

### 6단계: 마무리
- 원본 앱을 로컬에서 실행하여 이식 코드와 동작 차이가 없는지 확인할 필요가 있을 때만 수행한다.
- `openai_compat.py`를 실제 엔드포인트(또는 로컬 Ollama)로 1회 검증한다.
- 실행 방법과 설계 결정을 README로 정리한다.

### 7단계 이후 (별도 승인 필요)
- 플랫폼 연동은 핵심 패키지와 분리된 어댑터로 두고, 해당 플랫폼 약관과 자동화 정책을 먼저 확인한다.
- 승인 없는 자동 게시는 기본 동작으로 만들지 않는다.

## 7. 알려진 한계와 위험

| 항목 | 내용 |
|---|---|
| 안전 검사 | 정규식 기반이라 인신공격과 우회 표현을 잡지 못한다. 최종 방어선은 사람의 승인이다 |
| 비용 추정 | 모델이 usage를 반환하지 않으면 토큰과 비용이 0으로 기록될 수 있다 (로컬 모델에서 가능성) |
| 한도 의미 | 폐기한 초안은 응답 수에서 빠지므로 `max_replies`는 보낸 응답 기준이다. 무한 폐기는 시간 / 비용 한도로 막는다 |
| 성과 측정 | 어그로 감소 여부는 자동 측정이 불가능하다 |
| 확전 위험 | 상대에게 계속 반응할 빌미를 줄 수 있다. 짧고 평탄한 응답과 조기 종료를 기본 방향으로 한다 |
| 미검증 | `openai_compat.py` 실행, 원본 앱 실행 |
